## 🎯 Mission

**MajorCycle** is a premium financial terminal that runs a proprietary **Major Cycle** analysis on US, Australian, and Canadian equities. Users discover where stocks sit relative to their historical drawdown/recovery cycles, alongside fundamental health scores, valuation positioning, and analyst data.

The product launches as a **web app** with a **signed-in free tier** and a **7-day free trial** that converts to a monthly or annual subscription.

**Free vs premium (F3 Step 10 — owner-agreed).** Signing up is free and takes **no card**: a free account keeps Browse, the price chart, the drawdown overlay *with its cycle bands*, and every fundamentals/sentiment section — *the data is free; our analysis is paid*. **Premium is our judgement**: Overall Rating, Health Score, the Verdict, the scorecard/radar, rating badges, the downloadable report, and the entire screener (`/run`, `/results`). The trial starts at Stripe Checkout, not at signup. The rule lives in `web/lib/entitlement.ts` and is described in `docs/architecture.md` §7.1 — read it before touching anything that renders a score.

**This is not a financial advice product.** It is an educational/informational analysis tool. All copy, labels, and disclaimers reflect this.

## ⚠️ Non-Negotiables

These rules cannot be bent. If a task seems to require breaking one, **stop and ask**.

### Visual & UX

1. **The reference HTML is a REFERENCE, not a contract.** `/reference/original-design.html` is the mock-up the owner built to *show* what they had in mind before any code existed. Read it to understand the intent — the brand palette, the fonts, the density, the shape of each section. It is **not** a specification the live site has to match, and it is **not** evidence that anything currently on the site is correct.

    ⚠️ **This rule said the opposite until 2026-08-22**, and the cost was real: it read *"Any UI section with an equivalent MUST visually match it"*, so for months the answer to "why is it like this?" could be "because the mock-up is", and that ended the conversation. It ended one the same day — a design review flagged the accent stripes on "Why Attractive" / "Key Risks" and the honest answer was "the reference has them", which settles nothing about whether they should be on the live site. **A mock-up cannot tell you whether a decision is still right; it can only tell you what someone drew once.**

    **So: the live site is decided with the owner, not derived from the file.** When something on screen is only defensible by pointing at the reference, that is the signal to *ask*, not to close the question. Deviations no longer need justifying against it; they need to be deliberate, and the reasoning goes in `docs/design-system.md`, which is the living record of what the site actually does and why.

    ⚠️ **What has NOT changed:** the brand decisions in this file still bind (#25 colours, #26 fonts, #2 rating labels), accessibility is still a floor rather than a preference (#12), and "I felt like it" is still not a reason. What changed is only which document wins when they disagree — the owner does.

2. **Rating labels.** The five tiers are **High Conviction / Constructive / Neutral / Cautious / Bearish**. Never use "Buy", "Sell", "Strong Buy", "Avoid" in our scoring outputs. (Wall Street analyst recommendations from yfinance display verbatim — that's third-party data, not our judgment.)

3. **Mobile first.** Every page must be responsive down to 375px. No horizontal scroll on phones.

4. **Disclaimer presence.** Any page that displays a rating, score, or signal must have an "Information only — not financial advice" disclaimer visible without scrolling.

### Code

5. **All chart instances declared once** in master state — never redeclare with a standalone `let`/`const`.

6. **Never use `Math.max(...arr)` / `Math.min(...arr)`** on large arrays (>10k items). Use `reduce()`.

7. **Never put HTML comments (`<!-- -->`) inside JavaScript template literals.** Browser parser breaks.

    ⚠️ **A BACKTICK is the same defect and easier to type by accident** (2026-08-26). A CSS comment inside a template literal — `` /* .briefing is `display:flex` */ `` — terminates the literal there; the rest of the file becomes invalid syntax and the page renders **nothing at all**. Not a broken page, an *empty* one, from a line that reads as a comment. Use straight quotes inside any comment that lives in a template literal. ⚠️ And when you fix it, prove the script **ran** — the console buffer survives navigation, so a stale `SyntaxError` sits there looking current while the page works (`coding-standards.md` §38).

8. **CrosshairPlugin must guard against radar/doughnut/pie chart types** in `afterDraw` and `afterEvent` callbacks.

9. **DataProvider interface is sacred.** No code outside `analytics/providers/` may import `yfinance` directly. Phase 2 FMP migration must be a one-file change.

10. **Edit existing files with targeted edits only** — never rewrite a whole file unless explicitly asked.

11. **No `console.log`, no `print()`, no commented-out code** in committed files.

11a. **Never share-cache a response whose content varies by viewer.** `Cache-Control: public` / `s-maxage` is a **shared**-cache directive and Vercel's edge keys on the **URL alone** — so the first viewer's response is served to everyone else at that URL, *before your function runs*. That is an authorisation bypass, not a caching bug, and no in-function check can catch it. `/api/cycle` shipped exactly this while returning the full paid analysis (F3 Step 10, finding B1); it now sends `private, no-store`, and entitlement rides in the **query string** so the free and paid variants can never collide on one cache entry. If a response varies by viewer: put the varying dimension in the URL *and* keep the cache private, or use Next's server-side Data Cache. `pnpm check:entitlement-gates` fails CI if this regresses.

**It happened twice.** On 2026-07-29 the report-download route (`/stocks/[market]/[ticker]/report`) turned out to send **no `Cache-Control` at all** — on a response carrying the full scorecard — so its safety rested on Vercel happening not to cache it. Sending nothing is not the safe default; it is an unstated assumption about someone else's cache. **Every per-viewer response must say `private, no-store` explicitly**, including the refusals (our 402 names the caller's own denial reason). Note how it was found: an e2e assertion on the response header, written when the route became the report's only surface. Reading the code had not caught it, because the bug is a line that *isn't there*.

**And a third time, differently.** On 2026-07-30 `api/analyze.py` — the route returning a whole basket's paid analysis — turned out to send bare `no-store` rather than `private, no-store`. Vercel honours `no-store`, so nothing was ever exposed; the defect was that it was the **one** premium surface `pnpm check:entitlement-gates` did not assert, while it guarded the other three. Same root cause as the first two: **safe because of someone else's default, not because we said so.** The lesson has shifted from "say `private, no-store`" to "**say it AND guard it** — an unasserted header is one careless edit from being gone, and nothing will go red." The guard lives in the **`/api/analyze` section** of `scripts/check-entitlement-gates.mjs`, and it was verified to actually fail (weakened header → red; `s-maxage` injected → red) before being trusted. *(Cite guard sections by name, never by number: this sentence said "check 10" until 2026-08-01, when it turned out to mean the running total at the time of writing, which had since moved. The script now derives and prints its own count.)*

**A fourth time, and this one names the mechanism.** On 2026-08-01 `/api/portal` and `/api/checkout` turned out to send **no `Cache-Control` at all** — not a weak one, none — on payloads that are credential-equivalent and scoped to one customer: the portal's 303 `Location` is a live Customer Portal session granting that person's card, invoices and cancel button. Again nothing was exposed (Vercel caches only on `s-maxage`; both are POSTs), and again the safety was someone else's. **The mechanism to remember: Next attaches NO `Cache-Control` to route handlers.** Pages get `no-cache, must-revalidate` for free, so a habit formed on pages does not transfer, and "I didn't see a bad header" is not the same as "the header is right" — only **3 of 15** route handlers said anything. Read the wire, not the source. The guard is the **billing-endpoints section** of `scripts/check-entitlement-gates.mjs`, and it asserts the count of `headers: NO_STORE` **equals** the count of `NextResponse` returns, because one unguarded branch is the whole hole; it was proven to fail three ways before being trusted.

**A fifth time, 2026-08-23, and it was found by asking a DIFFERENT question.** The Layer G audit was building a test-coverage map, not hunting headers, and turned up five gated routes with no test AND no `Cache-Control`: `/api/search`, `/api/listings/search`, `/api/listings/status`, `/api/request-ticker` and the purge cron's own 401. ⚠️ **Reading the source said the wrong thing in BOTH directions.** Their signed-OUT refusals looked correct — but that header comes from the **proxy**, which sets `private, no-store` on its own 307 before any handler runs, so inspecting the refusal told you nothing about the response that carries the data. What sent nothing was the signed-IN 200, and only a wire read with a real session showed it. **The guard had been scoped to the two endpoints that bit us last time** and was silent about everything outside that list (14g); it now covers all seven, asserting every response in each file.

11b. **Withhold paid data at the data layer, not in the JSX — a hidden value is still shipped.** React serialises the props of client components into the RSC payload embedded in the HTML, so `{entitled && <Score value={cycle.overallRating} />}` hides the number on screen while the whole `cycle` object remains readable in View Source. Seen live on 2026-07-28: the page rendered `🔒 Unlock` while the source carried `"overallRating":60,"financialHealthScore":81`. **Strip restricted fields from the object before it can reach a client component** (`stripPremium()` in `web/lib/cycle.ts`), and treat the conditional render as presentation only. Every paid surface must require **two** things — the viewer's entitlement *and* the data's presence — so no single control failing open can expose the product. This bug class survives visual review precisely because the UI looks right: assert against the raw HTML, never against what's on screen.

11c. **One rule, one place. A rule written in two places drifts, and a third surface opts out of it by simply not being in either list.** Two instances, both found on the **live site** during the Layer F audit (2026-08-02) and both invisible to code review, because the defect is an omission rather than a wrong line. (i) `/pricing`, `UpgradeDialog` and `StartTrialModal` each kept a private list of "what a subscription includes"; when `/pricing`'s was corrected, the trial modal — **the last screen a reader sees before paying** — still sold three things a free account already had, while the dialog one click earlier listed the right four. Now one exported `PREMIUM_UNLOCKS` in `web/lib/pricing.ts`, and every line must name a field in `PREMIUM_FIELDS` or the screener. (ii) "Signed-out readers only" lived in `proxy.ts` (for `/login`, `/signup`) and again in `pricing/page.tsx`, so `/deletion-requested` — in neither — told **any** signed-in reader their account was scheduled for permanent deletion. Now one `SIGNED_OUT_ONLY_PATHS` list. **Being in `PUBLIC_PATHS` answers "may a signed-out reader in?", never "should a signed-in one see this?"** When you fix a claim on one surface, grep for every other surface making the same claim — and prefer extracting the constant over editing the words, or you have fixed the symptom and left the mechanism.

**(iii) A third instance, and this one is a NUMBER rather than a sentence — 2026-08-06.** One screener run offered two downloads, and Barrick's analyst target came out **CA$65.76** on the page, **65.76** in the `.xlsx` and **65.75** in the `.csv`. Three copies of "round to 2 decimals": `Intl` on screen, `toFixed(2)` in `ratings.ts`, `Math.round(v*100)/100` in `xlsx.ts`. `toFixed` and `Math.round` both round the **binary double**, which sits a hair below a half-cent, while `Intl` rounds the decimal the reader is shown — so the three parted company on ~4% of values, in *different* directions (65.755 splits the CSV off; 1.005 splits both exports off from the page). Note how invisible it was: every figure was plausible, all gates were green, and `ratings.ts` carried a comment promising the two files "always show identical figures". **Fixed by making one derive from the other** — `exportText` formats with the screen's `Intl`, and the workbook *parses its cell number back out of that string* rather than rounding again — so the workbook cannot drift from the CSV even in principle. ⚠️ **Extracting a shared constant is not enough when the rule is an ALGORITHM: two functions can share a spec and still disagree.** Make the second one consume the first's output. Guarded by `web/e2e/export-parity.spec.ts`, which imports both real functions rather than re-implementing either — a fourth copy inside the test would guard nothing.

**(viii) An eighth instance, and the copy was invisible to the guard built to find copies — 2026-08-23.** `compositionRamp()` in `lib/ratings.ts` colours the Health / Valuation / Cycle Payoff micro-bar under every Overall score, and it held its **own** table of the five tier colours — as `r,g,b` strings. They were the **pre-2026-08-22** values, so for a month the bar was painted in the old palette while the chip directly above it used the new one. Nobody saw it because the G6 change was a darkening, not a hue swap. ⚠️ **And `check:tier-palette` exists for precisely this**: it walks 278 files hunting stray copies of the palette — **by hex**. A copy written as `212,160,23` is invisible to it, so the one control against this drift had a blind spot the width of a format change. **Repainting the five literals would have left that blind spot intact and simply reset the clock**, which is why the copy was deleted instead: the triplet is now computed from `RATING_TIER_HEX`. Proven by setting one tier to magenta and watching the bar follow with no second edit. **When you find a second copy, ask whether you can delete it rather than correct it.**

**(iv) A fourth instance, and it is the cheapest one to repeat: I gave the rule to ONE of its two consumers — 2026-08-12.** Layer G's public chrome hides the nav on the two session-confined pages, because every link there bounces the reader straight back. `PublicHeader` asked the shared `showsFullChrome()`; `PublicFooter` was written ten minutes later and simply wasn't given it. Result: `/account/update-password` rendered a correctly collapsed header **above a footer still offering seven dead links** — on the page a reader mid-password-reset sees. Nothing errored, the constant existed and was correct, and code review would have read both files as fine. **Extracting the constant is only half the job; the other half is that every consumer actually consumes it.** Found by opening the page, not by reading it. Guarded by `e2e/public-chrome.spec.ts`, which asserts both components call the function *and* that neither holds a private path list — reading the source with comments STRIPPED, because the first version of that guard failed on the very sentence documenting the fix (twice now: see the `Markets · Live` note in the artifact build).

**(v) A fifth instance, and the second copy is written in ENGLISH — 2026-08-15.** Applying the legal audit put three live constants into published prose: the free tier's 25/day cap, the 30-day deletion window, the 3-day payment grace. Each now exists twice — once as a constant the product enforces, once as a sentence a customer relies on — and **the prose copy is invisible to every tool we own.** TypeScript cannot see it, no import links them, and the failure is silent in the worst way: tune `GRACE_DAYS` to 5 and the Terms do not error, do not look stale and do not stop rendering; they simply become a **false statement about what we do**, still fluent, still specific. ⚠️ Note this is the *reverse* of the defect that prompted the fix — the Terms had been **enforcing** a 25/day cap they never stated (11c's "one rule, one place", where one place was a nullity). Stating it fixed that and created this. **Where you write a number into copy, make the test build its assertion FROM the constant and check it against the RENDERED page** (14d: source-correct and screen-wrong is a real state), with an off-by-one control proving the match is value-sensitive rather than merely finding a digit. `e2e/legal-doc.spec.ts` does this for all three. **The general rule: a sentence that states a constant IS a copy of that constant, and prose is where copies go to drift unnoticed.**

**(vi) A sixth instance, in CSS, and the rule was reachable ONLY through an unrelated class — 2026-08-15.** The public site's document scale (24/17/13/12) lived as `.reading .legal-layout`, i.e. welded to the class that also builds the legal contents-rail **grid**. Correct while one kind of document existed. The Learn library made it two: those pages want the scale and *not* the grid, could not get it, and silently fell back to `.reading`'s own sizes — producing a **fourth type scale on the public site**, 36/26/20 against 24/17/13 everywhere else and 50/34 on the landing. Crossing from `/contact` into `/learn` was a **50% jump in heading size**. ⚠️ **Nobody wrote a wrong line.** `.reading` is the right default for a long page and the legal pages had opted out properly; the new pages simply had no reason to wear a class named after somebody else's layout. That is 11c-iv again — *the rule existed and one of its consumers never received it* — and the generalisation is: **if a decision is about documents, it is a class about documents.** A shared rule reachable only through an unrelated class is not shared. Fixed by extracting `.doc-scale`, with element selectors as well as helper classes, because article prose is authored as plain `<h2>` and content files should not need to know the design system's class names. ⚠️ **And it reversed a decision of mine that was defensible in isolation** — an article is read, a legal page is scanned, so it should keep the larger scale. Fine on its own terms; it created the fourth scale. **When a local choice is defensible, ask what it does to the SET**: never "is 17px right for an article?", always "how many scales does the site have after this?" Guarded by `legal-doc.spec.ts` + `learn.spec.ts`, which compare four surfaces **page-to-page** rather than against literals — plus a control asserting the real values, since four pages also agree perfectly when the stylesheet failed to load (14g).

**(vii) A seventh, and this one is INHERITED rather than copied — 2026-08-20.** A diagram
dropped into an article is inside `.reading`, so the prose stylesheet applies to it. `.reading ul`
sets `padding-left: 1.35em`; the limits figure draws its rows inside a `<ul>` and its "today" rule
as a sibling one level up, outside the list. Result: **every bar started 17.55px right of where
its own percentage said**, while the one line the figure exists to draw stayed put — so the rule
sat 17px from the bar it marks. ⚠️ **Nobody wrote a wrong line, and nothing was copied.** The
component's own CSS was correct; it simply arrived in a context that had opinions about `<ul>`.
Every earlier figure had the same inset and got away with it because nothing was aligned to them —
the defect was latent for four figures and only became visible when one of them needed two
elements to agree. ⚠️ And it read as **design**: 17px is a plausible gap, so review sees a
deliberate offset, and the width sweep found no overlap because nothing overlapped. Only measuring
`getBoundingClientRect()` on both elements and comparing them said otherwise. **When you place a
component inside prose, ask what the prose stylesheet does to its tags** — and where two elements
in a drawing must line up, assert that they do, because "looks aligned" is not a measurement.
Fixed with `.figure-list` (`design-system.md` §11), the same opt-out shape as `.heading-flush`.

**(x) A tenth instance, and the fix's OWN DOCSTRING named the consumer it never reached — 2026-08-25.** `fmtPerShare` in `lib/format.ts` says it exists *"mainly to fix the hardcoded '$' in EarningsHistory/DividendHistory so AUD/CAD render A$/CA$"*. **(ix) A ninth instance, and the second copy lives inside ANOTHER COMPANY'S system — 2026-08-25.** `PRICE_TABLE` in `lib/pricing.ts` renders the sticker on `/pricing`, `/account`, the upgrade dialog and the trial modal; Stripe's multi-currency Prices decide what the card is actually debited. **Nothing linked them**, and both directions of drift are silent: edit the table and we advertise a price Stripe will not charge; edit the Stripe price and we advertise one it no longer charges. 11f. **A page that asserts something about ONE reader must be gated on evidence that they ARE that reader — "signed out" is not evidence.** `/deletion-requested` says *"your account is now scheduled for permanent deletion"*. It was reachable by anyone who typed the URL, for the life of the site. It carries **no user data** and unlocks nothing but static prose; a marker that grants a page must never be able to stand in for a session, which `auth.spec.ts` asserts as a control. ⚠️ **Gate and setter fail differently:** a broken gate shows a stranger the page; a broken *setter* bounces the person who really deleted their account, and no gate test would notice — so `e2e/deletion-notice.spec.ts` presses the real button on a throwaway account.

11g. **A rule that MATCHES ON A STRING SOMEBODY ELSE OWNS must be tested against that person's actual strings — not against the phrases it was written from.** `friendlyAuthError` turns Supabase's raw errors into copy a non-technical reader can act on, and it silently failed to match **two** of the messages Supabase really sends: `"A user with this email address has already BEEN registered"` does not contain the substring `"already registered"`, and the 60-second reset cooldown — *"For security purposes, you can only request this after 51 seconds"* — contains neither `"rate limit"` nor `"too many"`. The cooldown is the one a real person actually meets, by pressing "Send reset link" twice. ⚠️ **Note why nothing was red:** the passthrough is *correct* behaviour for a genuinely unknown message, so a miss is indistinguishable from a design decision — there is no error, no log, and the page still renders. The only thing that can tell them apart is a test holding the upstream wording verbatim, which is what `e2e/auth-contracts.spec.ts` now does (found 2026-08-12; the same file's table also asserts every mapped message is a full sentence, which is how the second miss surfaced). Applies to every `includes()`/regex over a provider's text, an HTTP reason phrase, or a webhook's `reason` field. **Where the string is not yours, the test is the only place your guess stops being a guess.**

11h. **A third party's WIDGET RENDERING is not a third party's APPROVAL — and an absent error is not a passing check.** The Google sign-in button draws from an `accounts.google.com` iframe, with `google.accounts.id` live and a completely clean console, **on an origin Google has never heard of**. `renderButton` validates nothing; Google checks the origin server-side, when the popup opens. 11i-b. **Sometimes BOTH explanations are true at once (2026-08-15).** A break on the landing's ruler-label clamp stayed green twice. 11i. **A deliberate break that stays GREEN has two explanations, and the boring one is usually right — re-run before you touch the test.** This repo's whole safety net rests on breaking a guard on purpose before trusting it, so the one failure mode that quietly defeats that habit deserves its own rule: on 2026-08-13, building the legal-page contents rail, I deleted the CSS rule I believed made it stick, re-ran the guard, and it **passed**. The tempting conclusion is "my guard is useless" — and the instinct that follows is to weaken or delete a test that was working perfectly. The truth was that `next dev` served the previous stylesheet from `.next/cache`, even though `reuseExistingServer: false` had booted a brand-new server process; the **second** run compiled the change and went red for exactly the right reason (`Expected <= 2, Received 500`). ⚠️ **Before editing the assertion, print what the browser actually computed** (`getComputedStyle` / `getBoundingClientRect`). Doing that here separated the stale cache from two genuine findings: (i) the rule I had documented as load-bearing **was not** — the rail's own `max-height` clamp is what holds it, and either protection alone suffices, so my comment asserted a mechanism I had never broken; and (ii) the assertion `expect(railTop).toBeLessThanOrEqual(90)` **passed at −317**, i.e. with the rail scrolled clean off the top of the viewport — **a bound on one side only tests the direction that was never the failure mode.** ⚠️ **And the third: a FLAKY test is a finding, not noise.** In the same work one rail test went flaky — passed on retry, the most ignorable result a suite can give. Driving all eight clause links and printing each outcome, instead of re-running, showed that clicking clauses **05, 06, 07 or 08 all highlighted "Contact"**: the type had just been re-set 17px → 13px, which made the document short enough that those clauses sit where no scrolling reaches the scroll-spy's offset line, so its bottom-of-page rule won. **Nothing about the spy changed — the page got shorter.** Two habits: a flaky result on a test *you wrote this session* is far likelier to be your defect than the harness's, and **a type-size change is a layout change** whose second-order effects surface in anything that measures the page, including shared code several files away. The fix was an **opt-in** option on the shared hook rather than a new default, so the Stock Detail subnav and the offline report — both paid surfaces — stayed byte-identical: when a shared utility is wrong for a NEW caller, widen it for that caller instead of re-tuning it for everyone. ⚠️ **And the fourth, which is why "CI is green" is not a report: RECONCILE THE COUNT.** The commit adding a character-count guard came back **success** — local said **277 passed**, CI said **275**. Two apart, on a green run, and I nearly reported it as clean. The reconciliation is `275 passed + 2 flaky = 277`: Playwright prints retried passes on their **own** line and I had read only the last line matching `passed`. **Read the whole summary block, and when local and CI disagree, diff the test TITLES** — that separates *skipped* (a title missing on CI) from *retried* (a title appearing twice with `(retry #1)`). ⚠️ My first attempt at that diff returned **zero rows**, which looks like "no differences" and was actually a broken query: CI prints `e2e/legal-doc.spec.ts` and Windows prints `e2e\legal-doc.spec.ts`. The flakiness itself was mine — the guard's precondition polled until the article computed 13px, which proves the *stylesheet* applied and nothing about the column having taken its width or the real webfont rendering, and **font metrics are exactly what a character count depends on**. Local (8 cores, warm cache) never hit the window; CI (2 cores, cold compile) hit it twice, reporting 430 characters — the whole paragraph on one line. **A precondition must cover everything the measurement depends on, not merely something that correlates with readiness.** Full account in `coding-standards.md` §14, items 4–8. ⚠️ **And a fifth, 2026-08-23, which is the one that survives the discipline above.** The report route started answering **404** instead of 402 after the CSP flip. I did the right thing — `git stash`, three runs each side: **3 failures with the change, 3 passes without.** A clean controlled A/B. I then bisected: nonce off → passed; response header only → failed; a *benign* header of the same shape → passed; a short CSP → passed; a long permissive CSP → passed. Six consistent results telling one coherent story, which was **entirely false**. Every one of them was the `.next-dev` cache, which persists across `git stash`, across `reuseExistingServer: false`, and across a full server restart — so it sat underneath *both arms* of the experiment and moved with my edits rather than with the code under test. Moving `.next-dev` out of the repo and re-running gave **46 passed** on the unmodified change. ⚠️ Two habits. **Clear the build cache BETWEEN the arms of an A/B, not just before it** — a stash swaps the source, it does not swap what Turbopack has already compiled. **And treat an implausible mechanism as evidence against the experiment, not as a discovery**: "the header's NAME breaks route resolution but only on a dynamic route handler" should have been the moment to suspect the instrument, because no reading of Next's source supports it. A bisect inherits the contamination of everything it bisects.

11j. **"Approved" names a specific ARTIFACT. When a page is built from an approved design, the test must name its sections — which is why `e2e/how-it-works.spec.ts` asserts the folded-in headings **by name** rather than counting them. ⚠️ Practical rule: before reporting on any page with an approved design, `Artifact action:"list"` and read the artifact. 11k. **A number inside a DESIGN is data with a shelf life. Re-derive it, or the approved copy becomes a confident lie.** The landing storyboard was drawn from a real screener run and its prose stated *"5 rate Constructive or better"* and Tesla *"still comes sixth"*. Regenerating such a snapshot is a **content change**, not a data refresh. ⚠️ Related: **two snapshots describing the same subject must carry the same date.** Apple appears in both landing files; the first run left them a day apart and the page printed −12.2% in one section and −11.3% in another, three screens apart. 11l. **Where a colour is USED changes what it measures — and one function cannot answer both "what colour is this?" and "what can sit behind white text?"** Three findings from one contrast sweep, all invisible: (i) the screener's `.score-num` chips are white numerals on `scoreColor()`, and three of the five tier colours are far too light to be a background — Neutral gave **2.38:1**, the identical figure G2 fixed on the *badges*. The owner's instruction was *"whatever is present on the live site, the color should exactly match that."* **A real defect does not entitle you to widen your scope**; the accessibility finding was right and the unilateral repaint was not. Both surfaces are back on `scoreColor()`, and the debt is now carried honestly instead: a `[data-legacy-contrast]` marker on the subtree, excluded from the pass/fail set but **counted**, so it cannot silently grow and cannot quietly stop excusing anything. Fixing it is a product-wide Layer H job. **Record a defect you are not authorised to fix; do not fix it quietly and call it tidying.** (ii) The Neutral badge measured 4.73:1 on white and **4.32:1** on `--bg-page`; the badge did not change, what sat behind it did — composited colours must be measured where they actually sit. (iii) The dark honesty band reported **every** line as failing at ~1.1:1, on a band that is obviously navy, because `background: linear-gradient(…)` is a shorthand that resets `background-color` to transparent — so anything asking the DOM what is behind the text reads straight through to the page. That is the same bug already documented in `components/ui/button.tsx`; **write `background-color` + `background-image` separately whenever white text sits on a gradient.** ⚠️ The generalisation: a guard scoped to one class of route is silent, not clean, about the rest — see 14g.

11m. **A marketing page that SHOWS the product is a promise about the product — match the component, not the picture of it.** The landing's worked run advertises the screener, and every way it differed was a small lie a new customer meets on day one. Four, all found by reading `components/results/ResultsTable.tsx` rather than trusting the approved storyboard: **(i)** Overall and Rating Tier rendered as two columns; the product draws the score chip, the tier badge and the 40/35/25 composition bar in **one** cell, with "Rating Tier" a separate column the default view hides. **(ii)** Financial Health was coloured with `scoreColor` (five tiers) instead of `healthColor` (**three** — Healthy/Adequate/At Risk, at 80 and 60), so Tesla at 49.8 came out orange on the landing and red in the product. **(iii)** Both score cells carry their word (*Healthy*, *Reasonable*) and mine had dropped them. **(iv)** Current DD% is tinted `drawdown`, which runs **green for a deeper dip** because deeper is more cyclically favourable — I tinted it red, so the page's own illustration contradicted the page's argument. ⚠️ **The approved artifact is not a safe source for this.** It was hand-drawn in plain HTML from a screenshot, so it is only as accurate as whoever drew it; **the product's source is the sole authority on what the product looks like.** Reuse the real classes and the real helpers (`compositionRamp`, `healthColor`, `metricTintColor`) so the two cannot drift, and pull whatever extra field that needs into the snapshot rather than re-deriving it — the composition bar needed `cyclePayoffScore`, and computing it back out of the rounded total would have been a second implementation of the weighting (11c iii).

11n. **A fact can be written down CORRECTLY, twice, and still be missing — because it was filed under the wrong question.** The database region `us-east-1` was documented in `architecture.md` §2 and §5 before 2026-08-15, both times accurately, both times as a **latency** fact: it explains why the Vercel functions are pinned to `iad1` and why a DB round-trip is 10–20ms. 11o. **A command that succeeded is not a state that is true — and a hand-check can check the wrong copy.** Three instances in one afternoon (2026-08-16), all while proving a change to the `/learn` illustrations had actually reached the screen. (i) **`rm -rf` on a path that has never existed reports success.** I cleared `.next-dev/cache/images`; the dev image cache is `.next-dev/dev/cache/images` (prod: `.next/cache/images`). Nothing on the page or in the URL says which you are looking at. A note was not enough, so the launch config now runs **`start:fresh` (`pnpm build && next start`)**: starting `:3200` cannot serve stale code, because it rebuilds first. **The general rule: when a trap depends on a human remembering, spend the 25 seconds and make it structural.** ⚠️ Still name the server whenever both are running, and note `preview_start` will REUSE a running `:3200` without rebuilding — the guarantee is on a fresh start, not on an attach.

11p. **An asset you cannot regenerate is SOURCE, not output — and a probe that has never failed is not a check.** The three `/learn` illustrations are generated images, and **the same prompt returns a different picture**: different skyline, different valley shapes, a differently posed figure. ⚠️ **The checking half.** Every claim those pictures make was measured, and **three of the probes were themselves wrong** — each caught only by running it against a case whose answer was already known. The seam detector scored the *seamless* image at Δ14.6 (it was finding skyline towers). The teal-line check "confirmed" two falls matched over a sample that included the pale hills — **a contaminated sample yielding a confident number is worse than no number, because it looks like evidence.** The dimension reader was proven on four files of known size *before* being trusted on a paid 4K render, where "asked for 4K, silently got 1K" is invisible. **A probe you wrote five minutes ago has never been observed failing, so a pass from it carries no information: give it the case that must fail first.** ⚠️ And when instruments disagree, prefer the one that reads the artifact — `img.naturalWidth` reported `0` and `loaded:false` for three images that the network log and a screenshot both showed loading fine; it was reading mid-`srcset`. 11q. **A guard can be blind to the very thing that breaks the rule — so when a measurement disagrees with the screen, instrument the INSTRUMENT.** The contrast probe composited a colour's own alpha and never `opacity`, so text a reader saw at **3.38:1** was scored **6.81** and passed. `/learn` broke a compliance rule (#4/#12) with every check green. ⚠️ **The fix then broke the guard in the opposite direction**, and that is the more useful half: once the probe could see `opacity`, the landing's scroll-reveals — which rest at `opacity: 0` until scrolled into view — became *correctly* invisible text, so it measured **47 elements on a page carrying 291** and would have reported a clean page it had never looked at (14g). **Three diagnoses were wrong before that was clear**, each producing a plausible fix for a problem that did not exist: a wait for the loading fallback, a wait for the element count to settle, a wait for animations. What settled it was one number contradicting another — `bodyEls=581` beside `measured=47`. The DOM was **full**, so every "the page hasn't rendered" theory was answering a question nobody had asked. **Counting WHY elements were skipped gave the answer in one run after three rounds of guessing at timing**; that tally now ships in the probe and prints on failure. ⚠️ Two corollaries. **A plateau is not a finish** — waiting for "two equal readings" looked like settling and wasn't: the dev server serves a shell, pauses while it compiles, then streams, and two equal samples across that pause satisfied "stable" perfectly. Wait for a POSITIVE signal, and prefer the one the assertion itself demands (`MIN_MEASURED` is now both the wait and the floor, so they cannot disagree). **And recede with a colour, never with transparency** — a token can be measured; an `opacity` could not.

11r. **A file can exist for a reason nobody wrote down, and removal is the only way to find out.** `app/loading.tsx` was deleted to fix a sitewide soft-404 (every `notFound()` answered **200**, because the Suspense shell was flushed before the status was set) and a no-JS failure (four public pages showed only "Loading…"). **The deletion broke the build**, which is how its real job surfaced: `/login` and `/signup` call `useSearchParams()`, and Next refuses to statically prerender a page that does — that boundary had been satisfying the requirement **by accident, for the whole site**, and no comment anywhere said so. Reading the file could never have told you; only removing it did. ⚠️ **And the documented fix was the WRONG one here.** Next says to wrap in `<Suspense>`; a boundary renders its fallback on the server and fills in on the client, so a visitor without JavaScript would get the fallback and never the form — on the two pages that must work for everyone. `export const dynamic = 'force-dynamic'` resolves the params server-side instead, putting the real form in the HTML. **A framework's recommended fix is advice about the common case; check it against YOUR constraint before taking it.** Verified on the production build, because the defect was measured there and dev streams differently.

⚠️ **AND THE FIX WAS INCOMPLETE FOR FIVE DAYS, WHICH IS THE HALF WORTH REMEMBERING.** Deleting the ROOT `app/loading.tsx` fixed the public site and stopped there. `app/(app)/loading.tsx` was left in place — deliberately, and recorded in `architecture.md` §7.2 as *“the signed-in terminal keeps its skeleton”* — so **inside the product every `notFound()` still answered 200**: an unknown ticker and an unknown market both measured 200 on the production build while `/learn/not-a-real-article` correctly gave 404. Found 2026-08-23 by the Layer G coverage map, which noticed that the whole 523-test suite contained **one** assertion on a 404 status and it was for a Learn slug — **the route with no assertion on it was the one still broken.** Same bug, same mechanism, the half nobody re-checked (11c “one rule, one place”; 14g “a guard scoped to public routes is silent, not clean, about the rest”). ⚠️ **The trade-off that made it look unfixable was false.** Removing the remaining `loading.tsx` would cost the skeleton on the heaviest page we ship — so instead the existence check moved into `stocks/[market]/[ticker]/layout.tsx`, because Next nests a segment as `<Layout>` → `<Suspense fallback={<Loading/>}>` → `<Page/>` and **a layout renders OUTSIDE the boundary**. 404 restored, skeleton still painting at 389ms. ⚠️ Two wrong turns getting there, both caught by measuring rather than reasoning: keeping `(app)/loading.tsx` left it at 200 (that boundary sits above the new layout), and **a layout's `notFound()` is caught by the boundary ABOVE its segment**, so the friendly “Not in our coverage yet” page silently became the generic 404 — statuses green, customer experience worse.

11s. **A page's RENDER MODE is set by the whole tree, not by the page — and both ways of getting it wrong are silent.** Every page on this site rendered on demand until 2026-08-18, and the cause was one line in `app/not-found.tsx`: an async component calling `supabase.auth.getUser()` to personalise a single button. **The root not-found boundary sits in every route's tree**, so that one session read made the entire public site dynamic — and a dynamic route's prefetch is *skipped*, so every click paid a full server round trip. Measured: the prefetch payload for `/learn` was **210 bytes dynamic against 667 static**, and the click **674ms against 77ms**. Nobody wrote a wrong line; the cost simply landed nowhere near the cause. ⚠️ **The reverse is a SECURITY finding, and it happened during the fix.** Once the site started prerendering, four pages came along by accident — including `/deletion-requested`, which tells one person their account is being deleted, and which was measured on the wire sending `Cache-Control: s-maxage=31536000` (a **shared** cache directive, one-year life) where it had sent `private, no-cache, no-store`. Nothing was exposed, because `proxy.ts` gates it before the cache. **That is exactly the problem** — it is 11a's "safe because of someone else's default" for the fifth time. Every such page now states `force-dynamic` itself. ⚠️ **Guard the ARTIFACT, not the source** (11d): a page can declare `force-dynamic` and the build still disagree, so `scripts/check-render-modes.mjs` reads `.next/server/app/*.html` — the files Next actually emits — and asserts **both** columns, because a missing static page and an extra one fail in opposite directions. Broken on purpose three ways, the real one being to reintroduce the session read: **7 of 14 routes wrong**, with every page still rendering perfectly. **Before personalising anything in a shared layout, error page or template, ask what it does to the render mode of every route beneath it.**

11t. **A colour — or any value — fixed in ISOLATION can be correct on its own terms and still break the SET. And a suppression is only as good as its reason.** Two lessons from one day, 2026-08-22, and they compound. (i) Three rating colours were darkened for contrast, each measured against its own ground, each right. The change put **Cautious next to Bearish** — 10.7 apart on the perceptual scale, 10.0 to a red-green colour-blind reader — and no assertion in the palette guard could see it, because every one of them judged a single colour at a time. The **owner** caught it by looking. Fixing that then exposed the same defect one row up: the two greens were **8.2** apart, closer still. ⚠️ **The generalisable move is to ask what a local fix does to the set** — never "is this colour legible?", always "how far is it from its neighbours after this?" — and to encode the answer as a **ratchet** (today's measurement as the floor) rather than a threshold invented on the spot, because a guard that fails on the day it is written gets loosened rather than obeyed. `check-tier-palette.mjs` check 4 does this for every adjacent pair, in normal vision *and* two simulated colour blindnesses. Same family as design-system.md §11's "how many type scales does the site have after this?" (ii) The same day, an owner-approved suppression of a design-linter warning turned out to be **excusing a defect that no longer existed, for a reason that had never been true** ("scaleX would stretch the gradient" — measured, it does not), resting on a premise the owner had since removed, **and not taking effect anyway** — it had been verified once, four days earlier, with three controls, and nobody looked again. ⚠️ **A control verified once and never re-checked is a control you no longer have**, and an exemption that outlives its defect does not go quiet: it goes on excusing whatever wanders into its scope. Every exemption in this repo is therefore bounded on BOTH sides — it must still match at least one thing, or it comes out (14g). ⚠️ And note the near-miss in the diagnosis: an earlier session had blamed the re-firing on a stale tool cache, which *had* genuinely been stale once. **A plausible cause that is really present is the hardest kind of wrong explanation to catch** (14f, second instance).

11u. **A local server can make two values agree by a mechanism the production platform never promised — so "it matched locally" is not evidence they come from the same place.** The CSP flip mints a per-request nonce in `proxy.ts`. The renderer reads it off the **request** header and the browser enforces the **response** header, so those two must name the same nonce or every script on the page is refused: the page renders, looks finished, and does nothing. To check the guard could see that, I deliberately gave the response a second, freshly generated nonce — and the wire came back **matching**. Next's Node server copies every middleware response header back onto the request before rendering (`resolve-routes.js`: `resHeaders[key] = value; req.headers[key] = value`), so under `next start` the response silently wins both and no divergence is observable. **Vercel's edge is not obliged to do that copy.** The same code would therefore pass every local check and ship a dead page in production only — precisely the failure the owner cannot debug from outside. ⚠️ **The fix is not a sharper test, it is to make the agreement structural**: one string, built once, used for both, so there is nothing for a platform difference to pull apart. ⚠️ And note what the sabotage was actually worth. It did not confirm the guard; it revealed that the thing the guard watches for **cannot happen on this machine**, which is a more useful fact and the opposite of what a green result seemed to say. A break that fails to break is a finding about your model of the system, not a verdict on the test (11i). ⚠️ Same session, same shape, one level down: the strict form of that guard demanded a nonce on *every* script tag and went flaky, because a script with a `src` is judged by its URL against the allow-list and needs none — Google Identity Services injects exactly such a tag, so the check passed or failed on whether GIS had landed before `load`. **A probe that is stricter than the rule it enforces produces failures that are real-looking and meaningless.**

11v. **A paid surface cannot be audited where its engine does not run — and the sweep that cannot see the thing reports exactly what a clean system reports.** Layer 3's job is to prove no premium value reaches an unentitled viewer. Run against `localhost:3200` it returned a perfect result across 10 billing states × 5 surfaces: no premium keys anywhere. **It was worthless.** `/api/cycle` is a Vercel **Python** function and `next start` does not serve it, so on the local production build the entire cycle block renders *nothing* — no Overall Rating, no Verdict, and not even the **free** "Current Drawdown" or the "not available at this horizon" notice. There was no paid payload on the page for anyone, so of course none leaked. ⚠️ **Two instrument failures stacked, and both produce a clean bill of health.** The first needle searched for `"overallRating"` **with real quotes**; in the RSC payload the JSON sits inside a JavaScript string literal with every quote backslash-escaped, so it matched nothing at all. Fixing that exposed the larger environmental one above. ⚠️ **The fix is a POSITIVE CONTROL, not a sharper needle:** an *entitled* viewer's page MUST contain the premium keys, and if it does not the run prints "the search is broken, ignore every row above" and fails. The harness also **refuses to run against localhost** rather than emitting a number that looks like evidence. Re-run on the deployed preview it is genuinely clean — zero leaks across all seven denied states, 402 on both paid endpoints, 401 on `/api/cycle` in every state, `private`/`no-store` on all 50 responses. ⚠️ The generalisation, which cost twice in one day: **this product's paid surfaces cannot be measured on this machine.** The same environmental gap also invalidated the Lighthouse work (11w). Ask *"could this check see the defect if it were present?"* before believing a green result — 14g, one level up from the data.

11w. **Do not optimise against a number nobody can measure — and a fix that improves the artifact while the metric sits still is still a fix.** The ticker page's Lighthouse target (#33) was chased three ways on 2026-08-24. `/api/benchmarks` took a **third off the document** (3,019 → 2,004 KB) and the score **did not move**, because Lighthouse measures one cold load with an empty cache — the case a cross-page cache helps least. Splitting hydration across nine Suspense boundaries, which Next's own streaming guide prescribes, made it **worse** (83 → 73) and was reverted: that mechanism needs boundaries that actually *stream*, and synchronous ones buy overhead with no splitting. And measuring the deployed preview — on the reasoning that the local score was unfairly penalised by Australia→`us-east-1` latency — returned **64**, disproving the premise. ⚠️ **Neither available number is trustworthy** (three consecutive preview runs: 370, 540, 990 ms of blocking time), and **no external lab tool can reach a page behind sign-in**, so there is no third option. ⚠️ Two habits. **Prefer the measurement that does not depend on who took it** — byte counts are exact and were ratcheted into `check:page-weight` (1400 → 1250 → 1150 KB) precisely so a real saving cannot be given back in silence. **And when a target has no instrument, say so and leave the row red** rather than either abandoning it or, worse, changing the product to satisfy a reading you cannot trust — which nearly happened here.

11x. **Code-splitting decides where code LIVES; something has to stop CALLING it.** `AnalysisProvider` wraps every signed-in page, and its static import put the whole Supabase client — auth, token refresh, and a realtime module this app never uses — on the critical path of Browse and Stock Detail. Making the import dynamic was the obvious fix and **measured as achieving nothing**: the chunk still arrived before `load`. The provider fetched run history **on mount**, so the import fired immediately on every page regardless. Moving that fetch to `RunAnalysis` — the only consumer of `lastRun` — removed 62 KB transferred *and* a database round trip from every signed-in page. ⚠️ Both halves are needed, and the diff for the half that did nothing looks exactly as convincing as the half that worked. **Verify a bundling change by asking the browser what it fetched and when**, not by reading the import statement. ⚠️ And the behaviour moved had **no test** — a missing history fetch renders identically to a new account with no history. `e2e/run-history.spec.ts` now asserts both directions, with a control that the screener actually rendered first, since on an unentitled account `/run` is correctly the upsell and every assertion would otherwise pass while proving nothing.

11y. **A permission held back by only ONE layer cannot be tested, because its refusal is indistinguishable from silence — and an error code can be right for the wrong reason.** Supabase grants every privilege on a new public table to `anon` and `authenticated`, so safety rests entirely on row-level security. In July `authenticated`'s UPDATE on `profiles` was narrowed to three harmless columns; **its sibling `anon` was not**, and kept INSERT, UPDATE and DELETE on all 20 columns — `subscription_status` included — for a year (audit F-024, fixed 2026-08-25). It was never exploitable: the policy compares `auth.uid() = id`, and `auth.uid()` is NULL for an anonymous caller. ⚠️ **But look at what an anonymous UPDATE actually answered: `200`, no error, `0 rows`** — the identical response to "that row isn't yours" and to a client that silently did nothing. No observation could separate the system with the missing layer from the system without it, which is exactly why it survived a year of green checks. Revoking the grant makes it say `42501 permission denied for table profiles`, and **only then can a test hold the line**. ⚠️ **The code alone is not the assertion.** INSERT *already* answered 42501 before the fix — from the row *policy*, "violates row-level security policy" — so a guard matching the code would have passed on the broken state and proved nothing. `e2e/db-grants.spec.ts` asserts the **message**, in both directions: it must say "permission denied for table" and must **not** say "row-level security". ⚠️ **It was written down and not acted on**: migration `20260726010000` says of this exact grant *"Tightening that grant is tracked separately."* That is 11f again — a sentence in a comment is not a gate. ⚠️ **And "revoke everything" is not the lesson.** SELECT was deliberately kept: a cookie-bound server client whose JWT has just expired falls back to `anon`, and today that read answers "0 rows", which callers treat as "no entitlement" — the safe direction. Without the grant it would answer an error and break a paying customer's page mid-request. **Defence in depth is knowing which caller each grant serves**, so the guard's load-bearing control is not the refusals at all: it is that a real signed-in account can *still* save its display name. A database that refuses everyone passes every other assertion in the file. ⚠️ Postgres detail that decides the shape of the fix: **a column-level REVOKE cannot subtract from a table-level GRANT** — `REVOKE ALL` then grant back the one verb you want. ⚠️ **And the same over-grant was on all twelve tables** (F-026, closed the same day): the two public roles held every privilege everywhere, **`TRUNCATE` included — and row-level security does not govern TRUNCATE.** RLS filters SELECT/INSERT/UPDATE/DELETE; no policy touches a TRUNCATE, so for that one verb the layer everything else rests on was simply absent. Never reachable (PostgREST issues no TRUNCATE, and neither role has `rolcanlogin`), which is the point: this is where the F-024 story started too. Both roles now hold exactly what their policies allow and nothing on the nine policy-less tables — derived from `pg_policy` and a sweep of every `.from()` call site, never from memory. ⚠️ `REVOKE ALL` on `profiles` also drops its three-column UPDATE, so the migration re-grants it: **losing that line does not error, it silently stops `/account` saving.**

11ac. **A space you can see in the source is not a space the compiler emits — and where a rule lives in somebody else's compiler, only the rendered page can tell you.** The owner read the first article and said the space after two bold phrases was missing. It was present in the source, in both places, and every review, type check and all 649 tests agreed with the source. The cause is SWC: it drops the **leading whitespace of a JSX text node when that node spans more than one line AND contains an HTML entity.** Measured directly against `next/dist/build/swc`, holding everything else equal — `</strong> Aussie sixty
 biggest.` keeps its space, `</strong> Aussie&rsquo;s sixty
 biggest.` loses it, and the same entity on ONE line keeps it. Trailing whitespace is unaffected; a literal `’` is unaffected. ⚠️ **The failure is perfectly plausible output**: the paragraph renders, wraps and measures normally, and the only wrong thing is the boundary between an element and the text beside it — which is why a human reading the page found it and nothing else did. ⚠️ **Removing the entities fixed one file and protected nothing** — `learn/content.tsx` holds 151 of them, each a latent instance waiting for a bold phrase to be put in front of it. So the guard asserts the OUTCOME on the rendered DOM (`e2e/lib/proseSpacing.ts`), for every article in both sections, and stays true whatever the next cause turns out to be (11d). ⚠️ And the first version of that guard was a nuisance rather than a guard: it flagged a button sitting beside its caption, because inside a flex container the space between two children is `gap` and "no whitespace in the DOM" is the correct state. A sweep of the whole build output had already shown the same shape 56 times, every one a Learn legend swatch. **A check on text spacing must know which of its parents are prose.** ⚠️ **AND THE OUTCOME GUARD COULD ONLY REACH HALF THE PRODUCT, WHICH IS WHERE THE SECOND INSTANCE WAS — 2026-09-05.** `proseSpacing.ts` walks `/learn` and `/articles`: every prose surface reachable **without a session**. `OnboardingModal`'s Valuation bullet — one of four on the first-login compliance screen, and the only one written with `&apos;` — rendered **"Valuation Score— how far…"** while its three siblings kept their space, read straight out of the built chunk. **A guard's scope is a claim about what it can see** (14g), and "every surface I can render" is a claim about the harness, not about the product. Where the outcome cannot be observed, ban the **shape** in source instead and say which of the two you have: `e2e/jsx-entity-space.spec.ts` finds **1** instance across 85 multi-line text nodes, so the ban costs nothing. ⚠️ And it was found sideways — a mechanical sweep of the signed-in strings returned **2 flags, both false positives**, and one of those false positives was an entity, which prompted the targeted scan that found the real one. **A clean result from a sweep is worth reading for what it happens to show you.**

11ad. **The input you forgot to freeze is the one that moves — and it moves the FIGURE, not the data.** The first article's figures were re-run so every number came from one date, and one input was left live: `market_cap`, read from the database whenever the verification workbook was rebuilt. Market cap does not appear in the article at all. It decides **which sixty companies are "the largest sixty"**, so the nightly refresh silently re-ranked the group the article's headline figure describes: the workbook refused to build with the ASX 200 largest-60 median at **−18.5394** against the −18.4 printed four hours earlier. ⚠️ **Neither number was wrong.** Each was correct on its own inputs, both were plausible, and nothing about either looked odd — the only reason it surfaced is that the workbook asserts every published figure and stops rather than shipping a different one. ⚠️ The fix is not to re-pin the number: `reference/how-far-do-asx-shares-fall-DATA.json` now holds **every** input the figures derive from — drawdowns, market cap, sector, industry, name for all 871 companies — captured once, and the workbook reads only that. **When you freeze a measurement, freeze everything the measurement RANKS, GROUPS or FILTERS by, not just the values it prints.** Same family as 14g (a fix applied to stored data is undone by the next cron run) and 11k (a number inside a design is data with a shelf life).

11ae. **A sentence that names TWO mechanisms is TWO obligations — and implementing one of them makes the sentence read as done.** `architecture.md` has said since the pipeline was built that yfinance returns *"split- **and dividend**-adjusted prices relative to the latest bar"*, and then spent a full paragraph on the split half: a detection calendar, a full re-pull, a pending/resolve state machine, a sanity floor, three tests. **The dividend half was never implemented.** Each time a company goes ex-dividend the provider re-scales its entire prior series, so the nightly one-month window stored the new bars on the new basis and left every older bar — **the peak included** — on the old one. Measured on the live database: the ratio to a fresh pull was a **constant** on every bar before that company's last ex-dividend date and exactly 1.0000 after it (CBA 1.0169, GPT 1.0062–1.0244, MSFT 1.0019), so every drawdown read up to **two points deeper than the truth**, on the site and in a published article. ⚠️ **Nothing failed, in either direction.** A slightly-too-deep fall is a perfectly plausible fall; there is no error, no gap, no odd-looking chart, and no guard could have had an opinion. And the doc was *reassuring*: anyone checking whether adjustment was handled would read that paragraph and stop. **A correct sentence describing half-built work is worse than no sentence**, because it converts an open question into a closed one. ⚠️ It was found by asking a question nobody had asked before — comparing our own figures against a fresh provider pull, while auditing an article — which is the same move that found 11n. **When a doc names a mechanism, grep for the code that implements it; when you implement one of two named mechanisms, write down that the other is not done.** The fix mirrors the split path exactly (`_recent_dividends` → full re-pull), with the difference stated rather than assumed: a dividend adjustment is a smooth rescale that either happened or did not, so it needs **no** verify step, where a split can leave a real cliff and does.

11af. **A REPORT can be factually wrong and still be pointing at something real — investigate the observation, not the diagnosis.** The owner read the database and said *"for the dividend and stock split events you are using the same table and there is no way to distinguish between them."* Measured, that is false: `split_events` contains only splits, all 1,762 rows carry a split ratio, and nothing has ever written a dividend there. ⚠️ **The tempting reply is "actually they are already separate", which would have been true, verifiable, and would have closed the question on a real gap.** What was behind the observation is that **dividends had no table at all** — a dividend forces a full price re-pull exactly as a split does (11ae), and that re-pull left no record anywhere, so the database could not answer *"why was this company re-fetched last night?"* Reading the two side by side is precisely what makes an asymmetry look like a merge. **Non-experts describe the symptom in the vocabulary they have; the words can be wrong while the finger points true.** Answer with the measurement AND the thing they actually found. ⚠️ The same session produced the inverse and it is worth holding both: the owner said *"do not assume supabase is not working, try and then confirm."* I had read a session-start notice saying the connector was unauthorised and built around it, writing a migration I said I could not apply. **The connector worked on the first call.** A stated limitation is a claim like any other, and a claim about a tool you can simply *run* is the cheapest kind to check. ⚠️ And the separation that came out of it has a rule of its own: `dividend_events` is deliberately **not** `split_events` with a `kind` column, because a split is re-pulled AND VERIFIED (its history can be internally inconsistent and leave a real cliff — MNST, F-030) while a dividend adjustment is a smooth rescale that either happened or did not. `split_events` is a **state machine**; `dividend_events` is a **record**. Six columns would be permanently NULL on a dividend row, and a column that is null for half a table invites being read wrong. **One table per KIND of thing, where the kinds have different lifecycles.**

11ag. **A FALLBACK that has never fired is not protection, and a REFERENCE SERIES you measure against can itself lag.** Two findings from building the staleness sweep, both invisible to every existing check. ⚠️ (i) The Stooq price fallback has sat in `yfinance_provider.py` since Phase 1 as the documented answer to "yfinance is down". Driven through our own `_download_stooq`, it returns None for **every ticker in every market**, AAPL included: Stooq now sits behind a JavaScript bot check answering **404 to a request with no User-Agent — which is exactly what our code sends — and HTTP 200 with a 796-byte challenge page to one that has it.** That is 11z's shape in a second source, with the difference that it fails *safe* (HTML does not parse into OHLCV), which is why nobody noticed for months: a silent None from a dead source is indistinguishable from "this ticker isn't on Stooq". **A fallback's health has to be observable separately from its result.** ⚠️ **And measuring it reversed the plan.** The agreed design said to widen it to the nightly incremental path so it would stop being decorative. Stooq's bars are not on Yahoo's `auto_adjust` basis, so splicing them into a Yahoo series would put one company's history on **two adjustment bases** — the 11ae defect, deliberately reintroduced, hours after fixing it. **Before wiring a second source into the middle of a series, ask what basis its numbers are on.** ⚠️ (ii) Staleness is ranked against each market's benchmark index, because a calendar derived from the tickers being checked is blind in the only case that matters: with 869 companies current and one straggler, only two dates are in evidence, so the straggler ranks *one session behind* and passes. But the benchmark **lags its own market** — `^AXJO` reached 27 August while 247 ASX equities held the 28th — and looking each date up in the calendar scored *being one day more current* as maximally stale: **a false alarm covering nearly a whole market, on the owner's own market.** Every unit test passed; only running it against the live database showed it. Asking instead *"how many sessions are strictly newer than this bar?"* needs no special case and fails in the safe direction. **When you rank against a reference, handle "ahead of the reference" explicitly — and run the thing against real data before you believe it.**

11ab. **A class name is an IDENTIFIER, and reusing one inside a single stylesheet is a collision — which is invisible when both meanings render something plausible.** The owner asked for space around the `·` in *"26 August 2026 · 6 min read"*. It was implemented, shipped, and **never took effect**: the separator span was named `.art-dot`, and forty lines above it in the same file `.art-dot` was the chart's end-point marker — `position:absolute; width:7px; height:7px; border-radius:50%`. The separator therefore became a positioned circle contributing nothing to layout, so its padding did nothing. ⚠️ **Nothing looked wrong.** The `·` still painted roughly where a reader expects one; a screenshot, a review and every existing guard were all satisfied. ⚠️ **And three instruments disagreed before it was settled**: `getComputedStyle` reported `padding: 0px 7px` (true, and irrelevant to an absolutely-positioned box), a `Range` over the text nodes returned boxes that *overlapped* (incoherent), and only a **controlled experiment** — remove the padding, measure the line's width, restore it — gave a clean answer: the width never moved. **When measurements of a layout disagree, stop reading geometry and change one thing.** The guard is written as that same experiment, not as a geometry read, because the geometry read is what failed to see the defect. ⚠️ The tell worth remembering: `display` computed as `block` on a `<span>` whose siblings computed `inline`. A blockified inline is almost always something else's rule reaching it — a flex/grid parent, or, as here, a name you have used twice.

11aa. **A stale value that looks current is worse than a visible gap — so ask which of the two wrong answers a reader can SEE.** On 2026-08-27 the nightly refresh blanked `market_cap` for 15 of 863 companies because yfinance's `info` omitted the key, and the first fix made the writer OMIT the column so the stored figure survived. That is safe against one bad night and unsafe against a bad month: it would keep serving a months-old market cap as though it were today's, and nothing about it would ever look wrong. **The owner rejected it on 2026-08-29** — this product publishes what the provider gives it and never a figure of its own construction — and the reasoning generalises past this field. A null renders as an empty cell, which a reader can see and we can alarm on; a stale number renders as a plausible one, which nobody can see and no guard can find. ⚠️ **The two halves that make writing the null safe are the ones to keep.** The PROVIDER-side fallback asks `fast_info` when `info` has no cap — measured across 15 stocks in three markets, the two endpoints agree to a **median of 0.000%** (worst 0.85%, a price moving between two calls), so this is the same provider answering the same question a second way rather than a substitute figure; and the **>0.5% nightly invariant** is what makes a null self-correcting, because the next run restores it and the alarm fires if it does not. ⚠️ **And the incident recurred while the fix sat unmerged**: the 2026-08-28 run blanked 13 companies — AutoZone, Kroger, Lowe's, Micron again — because a scheduled workflow checks out the **default branch** (14g). Both endpoints carried a cap for all 13 when checked by hand, which is the evidence that the omission is transient and per-run rather than per-company.

11z. **A third party can fail you with a SUCCESS code — and then the obvious fix can land somewhere nothing reads it.** The ASX listings source returned **zero symbols every night for a month** (2026-07-24 → 2026-08-25, audit F-027) and nothing said so. Both were written from one run, so they stayed byte-identical — and `e2e/learn.spec.ts` was pointed at the frozen one, with a comment claiming the page reached the same fact *"through `lib/landing.ts`"*, the wrong module for a Learn page. It passed for four days. The first nightly rebuild made the two differ and it failed in the same second: **the page said 5.6%, the file it was reading said 8.0%.** ⚠️ **A guard aimed at the wrong source looks exactly like a guard aimed at the right one**, and no amount of re-reading the test finds it, because the assertion is true of both files. **After splitting one file into two, change one of them immediately** — a divergence you create on purpose is the only thing that proves every reader is pointed where you think. ⚠️ And the guard that was supposed to prevent this walked a **hand-written list of two source paths** and could not see a spec (14g, and the coverage map's own standing warning about hand-written lists). It is now derived — every file whose path says "learn" must not name the frozen file — **with comments stripped**, because its first run flagged the paragraph documenting the fix. That is the third time this repo has been caught by a guard reading its own explanation (11c-iv).

11av. **A NUMBER RESTATED IN PROSE IS A COPY, INCLUDING INSIDE THE SAME DOCUMENT.** 11c-v says a sentence stating a constant IS a copy of it; `consistency.py` was written for that rule and applied it only **across** files. Article 01 states its headline never-recovered rate three times — a bold sentence, a table, and the survivorship caveat 110 lines later. Two said **12.4%**; the third said **12.8%**, the value from before the 2026-08-30 dividend re-derivation moved 81 of the 464 asserted figures. That sentence was in no assertion, so it never moved with them, and a published article ended up disagreeing with itself about its own headline number. ⚠️ **Nothing could see it**: both are plausible percentages, the assertion suite has no opinion on prose, and a reader would have to hold one figure in mind across 110 lines. Only counting the DISTINCT VALUES of the same claim within one file finds it. ⚠️ **And the first version of the guard passed a deliberate sabotage**, because the markdown wraps at 80 columns and *"worse than"* sat on a different line from the figure it introduces — **a regex over prose must not assume a sentence is one line**; normalise whitespace first. ⚠️ Related, from the same pass: when re-deriving a published figure, **read the definition out of the assertion suite rather than inferring it from the column heading**. Two of my re-derivations disagreed with the articles until I noticed the second column is the highest **intraday high** since 2000, not the highest close.

11aw. **A SURFACE NOBODY LOOKS AT IS WHERE A DEFECT LIVES LONGEST — and "written twice by hand" is the shape to grep for.** P6 audited the five things a customer meets that never appear on a screen we own: the downloadable report, the transactional emails, the tags a crawler reads, robots/sitemap, and the production headers. **Nine findings; seven had no test of any kind**, and the two that did were covered by guards structurally unable to see them (14g). Two are worth carrying forward. ⚠️ **(i) Every email in this repo is written TWICE** — once as HTML, once as plain text, by hand, in the same function. The trial-welcome email’s button had been moved off `/results` (empty until a screen has been run) to `/stocks`, with a comment saying exactly why; **the plain-text copy twelve lines below still said `/results`**, and nothing compared them. That is 11c with both copies inside one function: close enough to read together, far enough apart to drift. The guard is ONE-DIRECTIONAL on purpose — every destination the HTML offers must appear in the text, never the reverse, because text legitimately spells out URLs that HTML hangs on words; a two-way check would fail on correct emails and be loosened within a week (11t). ⚠️ **(ii) A `'use server'` module was compiled into the 1 MB file customers download**, via `ReportDocument → KpiStrip → PremiumLock → UpgradeDialog → SupportDialog → ContactForm → contact/actions.ts` — **11d’s exact chain, one link further along**. It carried the Resend endpoint and a live `process.env.RESEND_API_KEY` read. **Nothing was exposed**, because esbuild left it as a runtime lookup and the `process` shim makes it `undefined` — which is the finding, not the mitigation: 11a’s "safe because of someone else’s default" for the sixth time, one `define` entry from baking a live key into a public artifact. And it was **dead code**: `check-report-sections.mjs` already said in its own comment that a lock can never render inside a report. Fixed by CLASS (any module whose first statement is `'use server'` becomes throwing stubs, so the next one is neutered on the day it arrives) rather than by naming that file, then asserted on the **emitted artifact** (11d). ⚠️ Two standing traps fired inside this one pass. The control on that artifact assertion caught **my own needles matching nothing** — they were in the HTML wrapper rather than in `report.js`, so the check would have been vacuous in both directions. And `check:tier-palette` failed on the **explanatory comment** of a fix, the fifth time this repo has been caught by a guard reading its own documentation (11au); reworded rather than teaching that guard to strip comments, because a naive stripper would cut at the `//` inside a URL and could hide a real literal after it. ⚠️ Finally, three things I nearly reported were **my test’s fault, not the code’s**: two omitted arguments, and a currency symbol typed from memory (`CA$` for a subscription that correctly says `C$`). **Where an assertion restates a value instead of importing it, the guard fails on the code rather than on the defect** (11c-iii).

11ax. **A RULE CAN MATCH YOUR FILTER AND STILL BE SKIPPED, FOR A SECOND REASON THE FILTER KNOWS NOTHING ABOUT — and the two instruments were blind in two different ways at once.** 11ap found that a checker's TAG LIST decides what it may notice. This is one layer deeper: `label-content-name-mismatch` **is** tagged `wcag21a`, which **is** in our `TAGS`, and axe still never ran it — because the rule also carries the tag `experimental`, and axe ships experimental rules `enabled: false`. It appeared in **no bucket at all**: not violations, not passes, not even *inapplicable*. So the honest question is never *"is it in our tags?"* but ***"did it run?"*** — which is why `e2e/lib/axeRules.ts` now asserts every one of the five was evaluated, and why removing the option makes the suite name all five and go red. ⚠️ **Lighthouse was blind to the SAME defect by a different mechanism**: it runs that audit and weights it **0**, so its accessibility category reported a clean **100** with a WCAG Level A failure inside it. Two tools, one defect, no signal from either — and neither was misconfigured, both were behaving exactly as designed. **Where a checker gives you a knob, write down what it consequently CANNOT see; where two checkers agree, check that either of them was looking.** ⚠️ What was actually wrong: an `aria-label` **replaces** an element's content when the accessible name is computed, so three controls advertised a name that appears nowhere on screen — the account button on **all six signed-in pages** named itself "Account menu" while displaying the reader's email. A speech-input user says what they see and nothing happens. ⚠️ **And restating the visible words in the label is NOT the fix, which cost a red run to learn.** `.kpi-label` is `text-transform: uppercase`, so the screen says "OVERALL RATING Unlock" while my carefully-matched prop said "Overall Rating Unlock": **a hand-written label is a guess at what CSS finally renders.** Delete the label and let the name come from the content, carrying any extra sentence in an `sr-only` span *inside* the control — then the name contains the visible text **by construction** rather than by your matching it (11c: delete the second copy rather than correct it). ⚠️ Finally, one of the three lived on a surface the guard could not reach: the shared E2E account holds no subscription, so `/run` renders the upsell and the CSV upload zone was never on the page being scanned. The file's own comment had called an entitled scan *"the obvious follow-up"* for two weeks. **A comment naming a gap is not a gate** (11f), and the entitled scan is the only reason that instance was found.

11d. **A second BUILD of the same components is a second product — test the artifact, never the source it came from.** The offline report (`web/report-bundle/`) is compiled by **esbuild**, not Next, from the same `.tsx` files the site uses. So `pnpm typecheck`, `pnpm lint` and every source-reading guard can be green while the thing a customer downloads is a **blank page** — which it was, for every stock, from **2026-08-01 to 2026-08-05**. The file was flawless on inspection (correct title, 2.6 MB payload, 1.09 MB script) and threw `ReferenceError: process is not defined` on load. **The cause was not in the report code at all**: `KpiStrip` → `PremiumLock` → `UpgradeDialog` → `next/link` pulled Next's client router in, and its module scope reads `process.env.__NEXT_ROUTER_BASEPATH`. esbuild's `define` rewrites only the **exact** string given, so the existing `process.env.NODE_ENV` entry left 14 siblings intact. Note the shape: **an import three components away, in a file nobody editing the report would open.** Fixed with a `process` shim in the bundle banner — a shim, not more `define` entries, so the next stray import *degrades* rather than blanks. The real protection is **`web/e2e/report-download.spec.ts`**, which downloads the actual file and opens it over `file://`, asserting it mounts, throws nothing and draws its charts — the **outcome**, so it stays valid when the next breakage is some other import. ⚠️ **It must be `file://`**: a blob URL in an iframe inherits the site's CSP, which blocks the inline script and blanks the page for a completely unrelated reason — an hour lost to a false positive. And e2e had *always* covered the report **route** (which returns JSON and was fine); covering a URL is not covering an artifact.

11e. **"I could not read it" and "it does not exist" are different answers — never let one return value mean both.** `fetchStockDetail` funnelled all four of its read-failure paths into the same `return null` that means *not in our universe*, and every caller then did the only thing that value permits: `notFound()` on the page, `404 Not found` from the report route. So a Supabase timeout reached a **paying subscriber as "Stock not found"** — a permanent answer to a transient problem, nothing logged, nothing to retry, and the owner cannot debug it from the outside. Fixed 2026-08-07: read failures throw `StockReadError` (carrying the PostgREST error as `cause`, so it survives into the Vercel logs), `null` keeps exactly one meaning, the route answers **503 + `Retry-After`** and the page reaches the existing "Try again" boundary. ⚠️ **Catch it in route handlers rather than letting it throw** — an uncaught error yields a 500 whose headers we don't set, and every response there is per-viewer (11a). **The second cost is worse than the first: it blinds you.** An intermittent 404 on an *entitled* viewer's report was read as an entitlement fault for an entire session, because the true cause was being swallowed one layer below where anyone was looking — the same shape as `check_invariants()` reporting zero violations over a universe missing the field it reads (14g). **An unreadable answer reported as a clean one is the most expensive kind of lie a program can tell.** Guarded by `web/e2e/stock-read-errors.spec.ts`, which drives the real `readStockRow`/`loadPriceBars` with a stub client — pure, credential-free, and carrying **controls** proving a genuine absence is still `null`, since "throw on everything" would otherwise pass every test.

**A THIRD TIME, 2026-08-27, AND THIS TIME THE WRONG ANSWER WROTE TO THE DATABASE.**
`getViewerEntitlement` funnelled its `profiles` read the same way — `const { data: profile }`,
error discarded, `if (!profile)` — so an unreadable row produced `acknowledgedDisclaimerAt: null`,
and `(app)/layout.tsx` gated the first-login disclaimer on that field alone. The owner, signed in
on an account that had acknowledged in **June**, was shown the onboarding gate. ⚠️ **The gate has
one button and it WRITES.** Pressing it stamped `now()` over the June date, and the original — a
compliance record under #23/#24 — is gone. Confirmed on the live DB: created `2026-06-15 12:54`,
acknowledged `2026-08-27 04:09`, while a sibling account created a day later still shows its own
three minutes after signup. ⚠️ **The generalisation is not "distinguish the two answers" — 11e
already said that. It is: ASK WHAT THE FALSE ANSWER LETS THE USER DO.** A wrong "not found" is
recoverable by reloading; a wrong "you have never agreed" hands the reader a button that destroys
the evidence they had. **Where a false negative leads to a WRITE, the write needs its own guard as
well as the read** — `acknowledgeDisclaimer` is now write-once (read first, plus `.is(…, null)` on
the UPDATE so two tabs cannot race), so being wrong costs nothing next time. ⚠️ And note where the
null came from: the `anon` SELECT grant kept deliberately in 11y, whose justification was that a
0-row read is *"the safe direction"*. **True for entitlement, exactly backwards for a flag whose
empty value means "prompt them, then write".** One value, two readers, opposite safe directions —
and only one reader had been considered. Guarded by `e2e/onboarding-gate.spec.ts`, whose control is
that entitlement still fails CLOSED on the same unreadable read.

**It happened again on 2026-08-23, and a FLAKY TEST is what exposed it** — the most ignorable result a suite can give. `/api/request-ticker` destructured only `data` from both of its lookups and discarded `error`, so a transient read failure was indistinguishable from an absent row. The two failures point opposite ways and **the second one writes**: a `listings` error told a reader their real stock was "not a known US/AU/CA listed stock", while a `stocks` error fell through to the upsert and **queued a request for a ticker we already cover**, which the nightly cron would then go and re-fetch — nothing errored, nothing logged, and the row was indistinguishable from a genuine reader request. Both now check `error` first and answer **503 + `Retry-After`**. ⚠️ Note it had **no tests at all** until that morning: the route was written, worked, and was never looked at again. `const { data } = await ...` is the shape to grep for.

**AND A FOURTH TIME, 2026-09-04 — FROM THE OTHER END. The endpoint learned the distinction and one of its two callers never did.** That August fix taught `/api/request-ticker` to answer **503 + `Retry-After`** rather than "not a known listing" when a read fails. `components/results/SkippedTickers.tsx` — the Request button on the **paid** results screen, right under "these tickers couldn't be scored" — was `if (res.ok)` and an empty `catch {}`. So all five distinguishable answers (400, 404, 409, 500, 503) collapsed back into silence at the last layer: the reader pressed Request, watched the button flip from "Requesting…" back to "Request", and was told nothing while **nothing had been queued**. Its sibling `components/request/RequestTicker.tsx` — same endpoint, same POST — has always surfaced the server's own message. ⚠️ **The comment is what made it survive review**, because it was right about one case and silent about the other four: *"a non-OK response (e.g. not a listed stock) leaves the ticker as-is — its smart chip already conveys that it can't be requested."* True of the 404. **A justification that covers the case you were thinking about reads as covering the case you were not.** ⚠️ The generalisation is the pair: **when you teach a server to say two things, grep for everyone who listens** — a fix applied at the layer where it was diagnosed is half a fix (11c-iv), and `if (res.ok)` with no `else` is the shape to grep for, exactly as `const { data } =` is one layer down.

### Data & Compliance

12. **All scores, labels, and ratings shown to users MUST be accompanied by disclaimers** on the page. Educational/informational only. Not financial advice. ASIC-compliant.

13. **Currency display:** Stock prices always shown in the stock's home currency (USD/AUD/CAD). Subscription pricing shown in user's local currency.

14. **Ticker storage format:** Use yfinance native format internally (`AAPL`, `BHP.AX`, `SHOP.TO`, `ABC.V`). URL routing maps `/stocks/au/BHP` ↔ `BHP.AX`.

    **One rule, one table — `MARKET_SUFFIXES` in `web/lib/ticker.ts`.** This rule lived in *four* places until 2026-08-04 and two of them knew only `.AX`/`.TO`, so TSX Venture (`.V`) silently classified as **US**. Nothing errored; the stock just claimed to be American. The Python side (`_infer_market`, twice) is cross-checked against itself by `analytics/tests/test_market_inference.py`.

    ⚠️ **Canada has TWO suffixes, so `.V` KEEPS its suffix in the URL** (`/stocks/ca/ABC.V`). `.AX`/`.TO` are stripped because one market has exactly one suffix; strip `.V` the same way and `ABC.V` and `ABC.TO` collide on `/stocks/ca/ABC` and one resolves to **the other company's data**.

    ⚠️ **The rule had NO real data behind it until 2026-09-02** — 1,454 `.V` symbols sat in the requestable menu and **zero** in `stocks`, so the whole path lived on a unit test. The owner asked for one to be pulled in; `AE.V` was queued through the real `ticker_requests` → `drain_requests` path and the rule works: `/stocks/ca/AE.V` renders, `/stocks/ca/AE` 404s. ⚠️ **And doing it immediately found what no test could**, which the OWNER then read more accurately than I did (5A-034, fixed 2026-09-02). `urlPartsToTicker()` returned early for a kept-suffix ticker — right, or it would build `AE.V.TO` — and thereby **never consulted the market argument at all**. I reported that as one wrong URL, `/stocks/us/AE.V`; the owner observed **all three markets** answer, which is the correct description of a parameter being ignored rather than mismatched. ⚠️ **And it was never really about `.V`.** `us` is the pass-through market, so any fully-qualified ticker resolved under it — **`/stocks/us/BHP.AX` served the Australian company.** Every other cross-market URL 404s **by accident**: the reconstruction happens to build a ticker nobody owns (`/stocks/ca/AAPL` → `AAPL.TO`). **An accident is not a rule**, so the agreement is now asserted — whatever we build must map BACK to the market in the URL, via the same `MARKET_SUFFIXES` table read the other way. ⚠️ **The fix belonged in the conversion, not in the page's gate.** My first proposal was one comparison in `layout.tsx`; four call sites use the conversion and **`lib/report-data.ts` is one of them**. A route handler does not render through a layout, so that fix would have left the **paid 1 MB report** downloadable at a wrong-market URL — 11c, caught only by grepping the consumers instead of fixing the surface I happened to be looking at. Returning `string | null` is what surfaced the other three: **the type error is the only thing that makes an omission visible.** **The lesson is still the shape: a rule whose case does not exist in the data is a rule nobody has run** — and the first person to exercise it found more of it than the person who wrote it down.

14a. **A daily bar's `date` is the exchange's OWN calendar date — never UTC.** yfinance stamps each bar at midnight in the exchange's timezone, so `tz_localize(None)` (drop the zone, keep local time) is correct and `tz_convert(None)` (to UTC first) is not. The difference is invisible for every exchange **west** of Greenwich and wrong for everything east: it stored **every ASX bar one day early, from inception to 2026-08-04** — 1,413,737 rows with **0 Fridays and 273,700 Sundays**, while US and Canadian data looked flawless. Even London (+1 under BST) was wrong. Guarded by `analytics/tests/test_no_utc_date_conversion.py`; the reasoning is in `data-contracts.md` (`PriceBar.date`).

14b. **A field's UNIT is declared once, in `analytics/providers/field_spec.py` — never in a comment beside a call site.** A mis-scaled number is still a plausible number, so neither review nor the type checker can see it. Three units were already learned the hard way and lived only as scattered comments: `dividendYield` arrives **already a percent** (×100 would make AAPL yield 35%), `debtToEquity` arrives **×100**, `payoutRatio` arrives as a **fraction**. Adding a `FundamentalsSnapshot` field without declaring its unit fails CI.

    ⚠️ **`0.0` from a provider is not always zero.** yfinance sends `grossMargins: 0.0` / `ebitdaMargins: 0.0` for every bank — meaning *not reported*. Scoring read that as a real 0%, the worst bucket, and marked **71 stocks** down for a metric that doesn't apply to them: 36 changed rating and **4 changed the label a customer reads** (C, WFC, SYF Neutral→Constructive; EQB.TO Cautious→Neutral). It also dragged the Financial Services peer median from 47.34% to 35.81%. `zero_means_na` covers **only the four margins** — a zero payout ratio, zero short interest and a debt-free balance sheet are all real, and 198 stocks genuinely pay no dividend. Applied on **write and on read**, so one bad row can't reach the scorer.

14c. **PostgREST returns at most 1000 rows and says nothing about it.** No error, no warning, no truncation flag — proven on the live DB, where an unpaginated read of `price_bars` (6.5M rows) returns 1000 and `listings` (8,964) is *already* silently truncated. This is a bug that arrives **with growth rather than with a commit**: the universe auto-expands on every reader's ticker request (#16), and `stocks` sat 133 rows from the cliff on 2026-08-05 with five unbounded reads — including the nightly refresh, which would simply have stopped enriching the overflow. Use `selectAll()` (`web/lib/supabase/paginate.ts`) or `_select_all()` (`daily_refresh.py`); `pnpm check:data-integrity` fails the build otherwise. Note where the fix had to come from: `daily_refresh.py` line 84 paginates *with a comment explaining the cap*, and line 489 in the same file on the same table did not. **The rule was written down; it just wasn't anywhere the second function could inherit it.**

14d. **The share-price currency is not the reporting currency.** `info['financialCurrency']` governs revenue, EBITDA, debt, cash, EPS and every statement blob; `info['currency']` governs the price, market cap and analyst targets. **79 of 863 stocks differ** — a fifth of the ASX names and a **third** of the Canadian ones (BHP.AX prices AUD / reports USD; A2M.AX reports NZD). We read only the price currency until 2026-08-05, so those statements rendered `A$` in front of US dollars, and `fcf_yield_pct` divided a USD numerator by an AUD denominator into the Financial Health score. Ask `statementCurrency(fundamentals)`, never `fundamentals.currency`; withhold a cross-currency ratio rather than publish it wrong. **A symbol alone is not enough** — in `en-US` the US dollar is a bare `$`, so a corrected BHP balance sheet reads `$15.7B` under a share price of `A$60.52` with nothing saying they differ (a gap of ~A$8B on that figure); `reportingCurrencyNote()` states it in words on the statement cards, and only when the two disagree. ⚠️ **This fix shipped INERT and only a screenshot caught it**: the field was added everywhere but left `null` on all 863 rows, and the fallback-to-price-currency is *correct*, so code, tests and guards all reported success while every page still showed `A$`. **When a fix depends on a new field, it is not done until that field is populated — assert on the rendered figure, not on the function that produces it.**

14e-3. **A rule enforced in one runtime is not enforced.** `normalise_fundamentals()` runs on write (provider) and on read (`web/api/cycle.py`, `analyze.py`) — all **Python**. The Key Metrics table renders from `web/lib/stocks.ts`, which is **TypeScript**, so 73 rows kept a cross-currency `fcf_yield_pct` *on screen* after the fix was written, tested, guarded and pushed. **Do not port the rule into the second language** — that is 11c's drift trap. **Assert the invariant on the DATA**: `check_invariants()` in `check_field_units.py` fails nightly on a stored `0.0` margin or a cross-currency FCF yield, covering every reader at once including ones not written yet.

14e-2. **A ratio is only safe when its numerator and denominator share a currency.** The scores are fine by design — Financial Health is built from ratios of statement figures, so the units cancel — with exactly one exception, `fcf_yield_pct` (cash flow ÷ market cap), now withheld. **But `pe_history` mixed them and it was on screen**: `_compute_pe_history` divides exchange prices by an income-statement EPS row, so Barrick's Valuation History chart read **19.2x** while the Key Metrics table on the *same page* said **10.1x** (Yahoo's `trailingPE` is currency-corrected; ours was not). Withheld for all 79 cross-currency stocks, not converted — one FX rate can't fix it, since rates move 15–30% across the five years plotted and distort the *shape* too. Before adding any new ratio, ask which currency each side is in.

14g. **A fix applied to STORED DATA is undone by the next cron run until the code is merged.** `daily_refresh.py` writes `"fundamentals"` as a **whole-object replace** for every ticker every night, and a `schedule`-triggered `actions/checkout` takes the **default branch** — so a backfill sitting on an unmerged branch has a shelf life of hours. Measured 2026-08-05: the US+CA refresh (22:30 UTC) reverted **608 of 863 rows** fourteen hours after they were fixed, while the 250 AU rows survived only because their workflow runs at 08:00 UTC — the split falls exactly on the workflow boundary. Consequences: **don't backfill before merging** (the post-merge refresh repairs every row from the provider anyway), and **never cite a DB reading as proof a fix is live** without checking `updated_at` against the cron schedule. ⚠️ **The instrument went blind, which is the real lesson**: `check_invariants()` reported *zero* cross-currency violations over that broken universe, because the reverted rows had lost the `financial_currency` field the test reads — **unmeasurable counted as clean**. Any check that needs a field must also assert that field is *present*, or it reports success precisely when things are most broken. Now a third invariant: >5% missing `financial_currency` is itself a breach (a proportion, so genuine upstream gaps don't cry wolf), and the nightly log prints invariant **names**, never a count.

14f. **Don't "fix" the 52-week high.** It comes from Yahoo as a real traded price, and `WeekRangeGauge` compares it with today's real price — same basis, correct. The printed high sits ~2% above the highest **close** of the year because it is an *intraday* extreme — the best price of one moment, which the end of that day almost never matches. **Owner decided 2026-08-05 to leave both alone** rather than invent our own figure and disagree with every broker a reader might cross-check.

⚠️ **This rule blamed that gap on dividend adjustment until 2026-08-19, and the correction is the lesson.** Our bars *are* dividend-adjusted (`auto_adjust=True`, deliberately: it makes returns comparable), so the mechanism named was real, present, and pointing the right way — it simply is not big enough to produce what anyone was looking at. Measured across 9 stocks in all three markets: quoted high vs our highest **close** = **+0.51% … +3.58%**; quoted high vs our highest **adjusted intraday high** = **−0.00% … +0.68%**, five of the nine agreeing to the cent. Dividends are the sliver; intraday-vs-close is the gap. **A plausible cause that is genuinely in the system is the hardest kind of wrong explanation to catch** — nothing contradicts it, so it survives review indefinitely. The cost is directional: anyone acting on the old sentence would go after the dividend adjustment, which works correctly and must not be touched. **When a doc attributes a number to a cause, the doc owes that number a measurement** — a mechanism that is *present* is not thereby the one *responsible*. Also note where it surfaced: not from reading the rule, but from writing `/learn/52-week-high`, where the same claim had to be explained to a stranger.

14h. **A provider's SECTOR is a classification, not a description — and an editorial claim about what companies DO cannot be read off one.** The first article said mining is *"a quarter of the ASX 200, fifty companies out of two hundred"*, counted as `sector == "Basic Materials"`. **The owner asked whether all fifty are actually miners. Six are not:** BlueScope makes steel, Sims recycles metal, James Hardie makes fibre cement, Fletcher Building makes building products, and Orica and Dyno Nobel make explosives — the last two sell *to* miners, which is a different business. Meanwhile six real miners sit under **Energy** (three thermal coal, three uranium). The published count of fifty happened to survive because the two errors cancelled; the reasoning behind it did not. ⚠️ **The larger defect was in a comparison nobody had questioned.** The sector table put ASX Basic Materials (−30.7%) beside the S&P 500's (−19.7%) — but the American sector is **20 companies of which 2 are miners**, the rest paint, fertiliser, industrial gases, cement and packaging. So the sentence "Australian miners fall half as far again as American ones" was comparing Australian miners with **American chemical companies**, and the eleven-point gap it cited was mostly that mismatch. Rewritten as the composition argument it always was — a quarter of the Australian index is mining against four in a thousand of the American one — the claim is both true and **stronger**. ⚠️ **Note what made this findable and what did not.** Every figure in the table was correctly computed from correctly stored data; nothing was red, and the fact-check sheet had cited an S&P factsheet for a number our own database had produced. It took a human asking *"are those really all miners?"* **Where an article characterises a group — miners, banks, tech — name the exclusions in the working and let the reader check them**, which is what sheet 9 of the article's workbook now does. And where a comparison crosses markets, check that the groups are composed alike before printing the gap between them.

14e. **The data pipeline is PINNED (`analytics/requirements-cron.txt`), and upgrading it is a PR.** `pip install "yfinance>=0.2.40"` in a nightly cron is an unreviewed deploy every night: an upstream release can change what a number *means* with no commit and nothing red. yfinance has already done it once (the `dividendYield` change above) — landing on a Tuesday, every yield on the site would have been 100× wrong by Wednesday. It was also drifting from dev unrecorded: the cron ran **1.5.2** while this machine had **1.3.0**. Because a pin only helps if you notice what the upgrade did, `analytics/cron/check_field_units.py` runs nightly and emails the owner when a field's **cohort median** leaves its declared band — the only instrument that sees a unit change, since every individual value still looks ordinary.

15. **Pre-computation policy:** Store raw price history + fundamentals only. Cycle math runs on demand. Never store rating outputs in the DB — they're always derived.

16. **Universe model:** Pre-seeded + auto-expanding. If a user uploads a ticker not in our universe, fetch it live, cache it forever, return results.

### Workflow

17. **Self-verification before "done".** Run **`pnpm gates`** and show passing output before reporting complete.

    ⚠️ **This said "run the appropriate command (`pnpm typecheck`, `pnpm lint`, `pnpm build`, `pytest`)" until 2026-08-24, and that list was never the whole set.** CI runs sixteen checks; that sentence named four, so "I ran the gates" meant "I ran the ones I could think of". The cost, audit finding **F-016**: a Layer 2 sweep that declared *everything automated* had silently skipped `ruff` and the `_engine` drift check, and six lint errors sat in a branch for a day until the first push went red. The cause was structural — every JS gate had a `pnpm` script and was therefore enumerable, while the Python gates and the drift check existed **only as steps inside `.github/workflows/ci.yml`**, so no local command could run them and no local list could be complete. **A gate absent from the list is a gate nobody runs, and nothing goes red, because nothing looked.**

    `scripts/gates.mjs` now runs all sixteen in one command, and — the part that matters — **it reads `ci.yml` and refuses to run at all if CI has a step it does not account for**, so the list cannot rot one step at a time. Proven both ways before being trusted: a fake CI step made it refuse and name the step; an orphan vendored file made it stop mid-run and enumerate every gate that consequently did **not** run. Three checks genuinely cannot run from a bare checkout (`check:page-weight`, `check:csp`, `lighthouse` — each needs a production server on `:3200`); they are printed as **NOT RUN with the reason**, never omitted, because silent omission is the whole defect.

18. **Zero tolerance on errors.** Zero TypeScript errors. Zero ESLint errors. Zero Python type errors. No warnings ignored.

19. **Never commit secrets.** All sensitive values live in `.env.local` (dev) or Vercel/GitHub Secrets (prod). Document required vars in `.env.example`.
