# Python dependencies for Vercel serverless functions in web/api/.
# These get bundled into each function's runtime image. Keep tight to stay
# well under the 250 MB function bundle limit.
#
# The data pipeline in analytics/ uses a superset of these (with yfinance etc.)
# — see analytics/pyproject.toml. The serverless functions never import
# yfinance: all data is read from Supabase, which the daily cron populates.
#
# ⚠️ EXACT versions since 2026-09-25. These were floors, so every Vercel deploy
# installed whatever PyPI had that minute: an unreviewed library upgrade riding
# along with any commit, which is the thing analytics/requirements-cron.txt was
# pinned to stop (CLAUDE.md 14e). Pinned to what CI and the live deploy resolved
# on that day, so nothing changed when this landed; an upgrade is now a PR, and
# the e2e job — which installs this file to run cycle.py — tests it first.
# ⚠️ pandas/numpy sit one patch ahead of the nightly pipeline's pins (3.0.6/2.5.3
# here, 3.0.5/2.5.1 there). Known and recorded, not accidental; align them in
# the same PR as the next deliberate upgrade.
pandas==3.0.6
numpy==2.5.3
supabase==2.31.0
# Direct Postgres connection for the screener's price fetch (web/api/analyze.py).
# The REST layer costs 700-1,200 ms per stock building JSON and gzipping it while
# Postgres itself takes 16-23 ms; this skips it. [binary] ships the libpq wheel so
# no system library is needed on the Vercel image.
psycopg[binary]==3.3.6
